# 完整性与逻辑评审员 · 方法参考

> 查两件事：① **完整性**（该有的有没有遗漏）；② **逻辑自检**（前后矛不矛盾、边界有没有漏）。
> 不评需求真伪（需求风险评审员）、不评体验（用户体验评审员）。

## 一、完整性：六维扫描（找遗漏，不是查格式）

不要只查"章节齐不齐"。按六个维度扫描 PRD，找功能遗漏——每维问"这里有没有漏考虑的场景"：

| 维度 | 扫描问题 | 常见遗漏 |
|---|---|---|
| **角色** | 每个角色都能完成任务吗？有角色被漏掉吗（管理员/访客/审核者）？ | 只写主角色，忘了其他角色的路径 |
| **时间** | 时间相关场景覆盖了吗（首次/重复/过期/超时/时区）？ | 忘了"过期""超时""首次与重复不同" |
| **状态** | 核心对象的状态流转完整吗？每个状态有进入/退出条件吗？ | 只写正常态，忘了失败/取消/中间态 |
| **权限** | 不同权限的人看到的/做的一样吗？权限边界清楚吗？ | 忘了"无权限时怎样""权限降级时怎样" |
| **关联影响** | 这个功能会影响现有功能吗？被影响的有说明吗？ | 新功能改了规则，没说对老功能的影响 |
| **反作用** | 用户可能误用/恶意用吗？有防范吗？ | 忘了"可能反复点""可能输入异常值" |

## 二、逻辑自检：查矛盾 + 穷边界

### 1. 前后矛盾
通读找打架：§2 说"支持每周重复"、§3 又写"每周仅限工作日"——到底支持还是限制？§0 痛点说"步骤多"、§2 设计还是 5 步——痛点没解决？

### 2. 同类项重复/散落
同一规则在多处重复（如"过滤非工作日"在 §2/§3/§0 都提）——该统一处定义、他处引用，否则改一处忘另一处。

### 3. 边界穷举（硬功夫）
对每个用例/规则，穷举边界：
- **空值**：字段为空怎样？
- **极值**：输入超大/超小怎样？
- **并发**：多用户/多窗口同时操作怎样？
- **异常**：网络断、服务错、数据冲突怎样？
- **状态转换**：A 状态能跳 B 吗？不能的话有提示吗？

## 三、问题记录格式

每个问题记：类型（完整性遗漏·哪维 / 逻辑矛盾 / 同类重复 / 边界缺失）/ 描述 / 位置（§几）/ 风险等级 / **AI确定度** / 建议。

## 示例

**完整性·角色遗漏**
- 问题：定时发送写了群聊/单聊用户，没写"被 @ 的成员"怎么接收/查看
- 位置：§2 选择发送对象
- 风险：中 ｜ AI确定度：确定有问题
- 建议：补"被 @ 成员的接收与查看"用例

**逻辑·边界缺失**
- 问题：定时任务到点，但用户网络断了——发不发、补不补、通知不通知？
- 位置：§2 主表单提交、§3 风险
- 风险：高 ｜ AI确定度：有依据的推测
- 建议：补"到点网络异常"的处理规则
